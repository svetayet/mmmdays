# MmmDays — дизайн-документ

Дата: 2026-10-25. Статус: на утверждении у пользовательницы.

## Зачем и для кого

Личный минималистичный трекер менструального цикла для одной пользовательницы.
Всё хранится локально в браузере — приватность важнее всего. Приложение должно
ощущаться профессиональным и уютным, им пользуются каждый день на телефоне.

Сейчас приложение живёт локально; позже будет выложено на https-хостинг, чтобы
устанавливаться на домашний экран телефона. Промо-сайт — отдельный будущий
проект, сюда не входит.

## Цели

- Отметка дня одним тапом: пусто → скудно → обильно → пусто.
- Реальный календарь (настоящие месяцы, не выдуманные сетки): листание свайпом
  и стрелками ‹ ›, дни кликабельны, сегодняшний день — тонкой рамкой.
- Статус сверху: «В процессе • N день» или «До начала: N дней» + строка
  «последний цикл: N дней».
- Страница статистики: последние (начало обильных), прогноз следующих,
  средняя длина цикла, средняя длительность, оценка ритма; столбчатая
  диаграмма «один столбик — один день» с выбором периода 3 / 6 / 9 / 12
  месяцев (по умолчанию 6); мини-календарь-карусель по полугодиям.
- Экспорт и импорт JSON — полный перенос данных вместе со статистикой.
- PWA: установка на экран телефона, запуск как нативного приложения, полный
  офлайн после первого открытия.
- Язык русский по умолчанию, английский — переключателем в углу.
- Юнит-тесты логики и документация (README на русском) — обязательные части
  поставки (явное требование пользовательницы).

## Не-цели (этот MVP)

- Без бэкенда, логинов, аккаунтов и синхронизации.
- Без напоминаний и push-уведомлений.
- Без медицинских советов, «фертильных окон», температуры и симптомов.
- Без нескольких профилей.
- Без переноса истории из других приложений — начинаем с чистого листа
  (подтверждено пользовательницей).

## Анти-цели

- Перегруженный интерфейс и «медицинские» термины. Только «скудно»,
  «обиль­но», «цикл», «ритм».
- Потеря данных: экспорт/импорт обязаны переносить всё; формат данных —
  версионированный и вперёд-совместимый.
- Выдуманные календари: только реальные даты реальных месяцев.
- Любая отправка данных куда-либо (никакой аналитики, трекеров).

## Согласованные решения (из брейншторма, подтверждены)

- **Навигация:** две вкладки внизу — «Календарь» и «Статистика» (выбран
  вариант с вкладками).
- **Главный экран:** статус-карточка сверху, под ней календарь текущего
  месяца.
- **Диаграмма:** тонкие столбики, один столбик = один день, высота 0/1/2 по
  интенсивности; периоды 3 / 6 / 9 / 12 месяцев.
- **Мини-календарь на статистике:** карусель по полугодиям — один лист = 6
  месяцев, лежат по 2 месяца в ряд (3 ряда), с читаемыми числами (~9–10px);
  свайп или стрелки ‹ › листают полугодиями, точки показывают число листов;
  дальше текущего полугодия листать нельзя. Страница статистики
  прокручивается: цифры и диаграмма — на первом экране, календарь ниже
  (проверено на макете, пользовательницу устраивает).
- **Расчёты — по обильным дням:** цикл начинается с первого обильного дня
  периода; «последний цикл: N дней» — дни между началами обильных; прогноз =
  дата последнего начала обильных + средняя длина цикла; «ритм: ровно» —
  если разброс длин циклов ≤ 2 дней.
- **Язык:** русский по умолчанию, переключатель RU/EN в углу.

## Правила подсчёта (спецификация логики)

Состояние дня: 0 — нет данных, 1 — скудно, 2 — обильно.

**Период** — непрерывная последовательность отмеченных дней (1 или 2);
один неотмеченный день внутри периода не разрывает его, разрыв в 2 и более
дней — разрывает. Длительность периода — от первого до последнего
отмеченного дня включительно (с внутренними пропусками).

**Начало цикла** — первый обильный (2) день периода. Если в периоде нет
обильных дней, он показывается в календаре и диаграмме, но в подсчёте
циклов не участвует.

**Длина цикла** — разность дат соседних начал циклов, в днях.

**Средняя длина цикла** — среднее арифметическое длин всех циклов,
округлённое до целого. Меньше 2 циклов — «мало данных».

**Средняя длительность** — среднее число обильных дней в периоде
(«длится» считается по обильным), округлённое до целого. Периоды без
обильных дней не учитываются. Нет периодов с обильными — «—».

*(Уточнено пользователем 2026-10-25: раньше считалась длина периода
от начала до конца, включая скудные дни.)*

**Статус «В процессе • N день»:** сегодня отмечен, либо сегодня не отмечен,
но последняя отметка периода была вчера (допуск одного дня ещё не
разрешён). Со второго дня без отметок статус уходит на «До начала». N =
сегодня − первый обильный день периода + 1; если обильных в периоде ещё
нет, N = сегодня − первый отмеченный день периода + 1. (Правило «ещё один
день "В процессе"» подтверждено пользовательницей: статус не должен
«прыгать» при однодневной паузе внутри периода.)

**Статус «До начала: N дней»:** сегодня вне периода. N = прогнозная дата −
сегодня. Если прогнозная дата прошла, показываем «задержка N дней» (N —
сколько дней назад). Мой выбор формулировки — можно поправить.

**Прогноз следующей** = дата последнего начала цикла + средняя длина
цикла. Мало данных (меньше 2 циклов) — прогноз не показываем, только
«мало данных».

**Ритм:** меньше 2 циклов — «мало данных»; разброс (max−min) длин циклов
≤ 2 дней — «ровно»; 3–5 — «неровно»; больше 5 — «нерегулярно». Пороги
кроме «ровно» — мой выбор.

**Сегодняшний день** в большом и мини-календаре помечается тонкой рамкой
(box-shadow-кольцо), не перекрывающей отметку интенсивности.

## Хранение данных

- `localStorage`, ключ `mmmdays.v1`.
- Формат (мой вариант, компактнее строковых статусов):

```json
{
  "v": 1,
  "days": { "2026-10-20": 1, "2026-10-21": 2 }
}
```

- Даты локальные, `YYYY-MM-DD`. Поле `v` — версия формата для будущих
  миграций.
- **Экспорт:** скачивается файл `mmmdays-backup-YYYY-MM-DD.json` — тот же
  объект плюс поле `exportedAt`. Экспортируются все данные.
- **Импорт:** объединение с текущими данными; при совпадении даты побеждает
  значение из файла; перед применением — подтверждение с числом дней,
  которые добавятся/заменятся. Битый или чужой файл — понятная ошибка,
  ничего не ломаем.
- Выбранный язык хранится там же (отдельный ключ `mmmdays.lang`: `ru`/`en`;
  нет ключа — русский).

## Локализация

- Два словаря: `ru` и `en`, без библиотек.
- Названия месяцев и дней недели, формат дат — через `Intl.DateTimeFormat`
  с выбранной локалью (не через словарь).
- Переключатель RU/EN в углу шапки; выбор запоминается.

## Технологии (решение принято на мне, пользовательница делегировала)

- **Vite + TypeScript, без UI-фреймворков** (vanilla TS + CSS). Приложение
  маленькое, фреймворк не нужен; сборка через Vite даёт dev-сервер, быструю
  сборку и лёгкий статический результат — ровно те html/js/css и манифест,
  которые потом лягут на хостинг.
- **Vitest** для юнит-тестов. Вся логика расчётов — чистые функции без
  DOM (разбиение на периоды, циклы, средние, прогноз, ритм, экспорт/импорт),
  тестируются целиком.
- **PWA:** Web App Manifest + иконки (192, 512, maskable) + service worker
  для офлайна (vite-plugin-pwa или ручной SW — на усмотрение строителя;
  требование: после первого открытия работает без сети).
- Service worker требует http(s): локально — dev-сервер Vite (`npm run dev`)
  или любой статический сервер для сборки; на хостинге будет https.
- **Основное устройство — Android/Chrome** (подтверждено). iOS
  поддерживаем базово (apple-touch-icon, safe-area), но полировку установки
  и офлайна и ручные проверки делаем под Android.
- **Публикация — вне этой работы** (пользовательница выложит сама).
  Сборка с относительными путями (`base: './'`): работает и в корне
  домена, и в подпапке вроде GitHub Pages; README опишет выкладку.
- **Проверка PWA на телефоне до хостинга:** по USB через chrome://inspect
  (port forwarding) — телефон видит приложение как localhost, service
  worker и установка работают. По Wi-Fi через IP компьютера откроется
  только интерфейс без установки и офлайна (http — не безопасный контекст
  для service worker). Это опишу в README.

## Дизайн-система

Палитра (согласована):

| Роль | Цвет |
|---|---|
| Фон | `#F5F6F7` |
| Карточки | `#FFFFFF` |
| Акцент (скудно) | `#F4C6CC` |
| Сильный акцент (обильный, активное) | `#E89AA4` |
| Текст | `#2B2B2B` |
| Вторичный текст | `#8A8F98` |
| Границы, пустые дни | `#E4E6E9` |

- Карточки: радиус ~18px, мягкая тень `0 4px 14px rgba(43,43,43,.06)`.
- Круглые элементы: дни-круги, чипсы-пилюли (радиус 999px), таб-бар — белая
  пилюля внизу, активная вкладка цветом `#E89AA4`.
- Типографика: системный стек (`system-ui, -apple-system, sans-serif`),
  минимум текста.
- Иконки приложения: нейтральный знак в палитре, без медицинской
  символики (мой выбор: мягкий круг в розовой гамме на светлом фоне).
- Вкладка «Статистика» — заголовок, карточки «Последние» и «Прогноз»,
  три плитки (цикл / длится / ритм), чипсы периода + диаграмма, ниже —
  карусель мини-календаря; внизу страницы карточка «Данные» с кнопками
  экспорта и импорта JSON (моё решение о размещении).

## Экраны

1. **Календарь (главная).** Статус-карточка; заголовок месяца со стрелками;
   сетка месяца (неделя с понедельника); тап по дню переключает состояние по
   циклу; today — рамочка; маленькая легенда под календарем; таб-бар.
2. **Статистика.** Как описано выше, страница прокручивается.
3. **Переключатель языка** — в шапке, угол.

## Тестирование

- Vitest: разбиение на периоды (включая пропуск ≤1 дня и разрыв), границы
  месяцев и годов, подсчёт циклов только по обильным, средние, прогноз,
  ритм по порогам, статусы («В процессе», «До начала», «задержка»),
  краевые случаи (нет данных, один день, только скудные дни, прогноз в
  прошлом), сериализация экспорта и объединение импорта (включая битые
  файлы).
- Логика дат работает с реальными календарями: високосные годы, разная
  длина месяцев.
- Установка PWA и полный офлайн проверяются вручную после публикации на
  хостинг; локально — через dev-сервер.
