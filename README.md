# MmmDays

Минималистичный трекер цикла — PWA, которая ставится на телефон с сайта и работает полностью офлайн.

## Что это и для кого

Три экрана: **Календарь** (отметка дней — тап по дате: ничего → скудно → обильно → ничего; статус и прогноз сверху), **Статистика** (последние месячные, прогноз, средняя длина цикла и длительность, «ритм», диаграмма за 3/6/9/12 месяцев, мини-календарь за полугодия с прокруткой истории) и **Настройки** (светлая/тёмная тема, учёт скудных дней в расчётах, экспорт/импорт).

**Приватность — главная фича:** все данные живут в `localStorage` вашего браузера. Ни аккаунтов, ни аналитики, ни трекеров; данные никуда не отправляются. Service worker кеширует файлы приложения, и оно работает офлайн — онлайн браузер лишь изредка проверяет на том же хостинге, не обновились ли сами файлы приложения.

Как считается:

- Цикл начинается с первого **обильного** дня; скудные дни до/после — часть той же менструации (разрыв ≤ 1 день склеивается).
- Длительность считается **по обильным дням**: «скудно, скудно, обильно» — длится один день.
- В настройках есть переключатель **«Учитывать скудные дни»**: включив его, расчёты начинают считать скудные дни полноправными — началом цикла считается первый отмеченный день, длительность — вся менструация целиком. По умолчанию выключен.
- Прогноз = последнее обильное начало + средняя длина цикла (нужно ≥ 2 цикла).
- «Ритм: ровно» — разброс длин циклов ≤ 2 дней; 3–5 — «неровно»; больше — «нерегулярно».

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
```

## Тесты

```bash
npm run test       # vitest, все юнит- и DOM-тесты
```

## Сборка

```bash
npm run build
```

В `dist/` получается готовый к размещению сайт: `index.html`, `assets/` (js/css с хешами), `sw.js` + `registerSW.js` (офлайн-кеш), `manifest.webmanifest`, `icons/`. Все пути относительные (`base: './'`), поэтому сборка работает и в подпапке.

## Как выложить на хостинг

Любой статический хостинг — GitHub Pages, Netlify, Vercel, Cloudflare Pages, свой nginx: просто отдайте содержимое `dist/`.

Пример с GitHub Pages (проект в репозитории `user.github.io/<имя>` или в подпапке):

1. `npm run build`
2. Опубликуйте `dist/` (например, ветка `gh-pages` через `npx gh-pages -d dist`)
3. Откройте адрес на телефоне в Chrome → меню → **«Установить приложение»** (или «Добавить на главный экран»)
4. После установки приложение работает без сети

## Как проверить на телефоне до хостинга

**Через USB (полноценная проверка, включая установку и офлайн):**

1. Телефон: Настройки → Для разработчиков → Отладка по USB
2. Компьютер: `npm run dev -- --host`
3. Chrome на компьютере → `chrome://inspect` → **Port forwarding**: `8080` → `localhost:5173`
4. На телефоне откройте `http://localhost:8080` — для браузера это «безопасный контекст», поэтому установка и service worker работают как на хостинге
5. «Установить приложение» → отключите USB и сеть → приложение открывается офлайн

**По Wi-Fi (только посмотреть интерфейс):** `npm run dev -- --host`, на телефоне `http://<IP-компьютера>:5173`. Service worker и установка требуют HTTPS или localhost — по Wi-Fi они не заработают, это ограничение браузера, а не приложения.

Данные при этом хранятся в браузере телефона (при заходе с телефона) или компьютера (при заходе с компьютера) — это разные хранилища; перенести данные можно экспортом/импортом.

## Экспорт и импорт данных

Экран **Настройки → Данные**:

- **Экспорт JSON** — скачивает `mmmdays-backup-ГГГГ-ММ-ДД.json`:
  ```json
  { "v": 1, "days": { "2026-10-15": 2, "2026-10-16": 1 }, "exportedAt": "…" }
  ```
  (`1` — скудный день, `2` — обильный)
- **Импорт JSON** — файл проверяется на формат, затем показывается подтверждение («Добавится N дней, заменится M. Применить?») и данные сливаются: значения из файла побеждают на конфликтах, существующие отметки не из файла сохраняются.

Так же переносится история между устройствами: экспорт на одном → импорт на другом.

## Структура проекта

| Путь | Что там |
| --- | --- |
| `src/logic/` | Чистые функции: даты (`dates.ts`), разбор менструаций (`periods.ts`), статистика циклов (`cycles.ts`), статус-строка (`status.ts`) — всё покрыто юнит-тестами |
| `src/views/` | Экраны: календарь (`calendarView.ts`), статистика (`statsView.ts`) — тонкие DOM-модули |
| `src/ui/` | Переиспользуемые виджеты: диаграмма (`chart.ts`), мини-календарь-карусель (`miniCal.ts`) |
| `src/i18n/` | Словари ru/en и хелперы (падежи слов «день/дня/дней», названия месяцев) |
| `src/storage.ts`, `src/store.ts` | Чтение/запись `localStorage` и стор с подписками (единственный источник правды) |
| `src/dataio.ts` | Экспорт/импорт бэкапов |
| `scripts/gen-icons.mjs` | Генератор PNG-иконок без зависимостей (`node scripts/gen-icons.mjs`) |
| `docs/superpowers/` | Дизайн-документ и план реализации |

## Стек

- [Vite](https://vitejs.dev) + TypeScript (strict)
- Без UI-фреймворков и без runtime-зависимостей — итоговый бандл ~17 КБ (gzip ~6 КБ)
- Vitest + happy-dom для тестов
- vite-plugin-pwa для manifest и service worker (dev-зависимость)

Известная мелочь: `npm audit` показывает предупреждения только по dev-зависимостям тестовой среды (happy-dom, vitest) — в собираемое приложение они не попадают.

## Лицензия

Личное использование. Проект создан для себя; никакие данные никуда не отправляются.
